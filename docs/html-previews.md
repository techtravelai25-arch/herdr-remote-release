# Local HTML previews

Requires the Android app and laptop companion 0.8.32 or later.

Tap an `.html` or `.htm` link in a conversation, or open an HTML file in Files
or Results. The app opens the page with Back and Refresh controls. Interactive
JavaScript, nearby CSS, images, fonts, JSON, and linked HTML pages are supported.
Pinch to zoom when a page was designed for a desktop screen.

The laptop must remain awake and connected. Relay connections carry page
content through the existing encrypted relay. No public URL, new deployment,
or additional service is needed. Direct tunnel mode uses its existing
authenticated HTTPS connection instead.

## Supported targets

- Relative paths such as `output/report.html` and `./output/report.html`.
- Absolute paths or `file://` URLs within the selected session's folder.
- `.lavish/report.html` links generated by local visualization tools.
- Explicit HTTP loopback URLs such as `http://localhost:3000/` or
  `http://127.0.0.1:8080/report.html`, on ports 1024–65535.

Use Markdown links for file names containing spaces. File links may include an
anchor or a trailing line number. Resources must stay in the page's directory
or its subdirectories. Symlinks, hardlinks, hidden/credential files, traversal,
and pages outside the authorized project/session folder are rejected.

This is a static page preview. External CDN scripts, remote resources, forms,
iframes, workers, cookies, and general development-server API calls are blocked.
Use self-contained HTML or place its dependencies beside it. Localhost targets
must have no credentials or query string; redirects are rejected. Clicking a
localhost URL sends a GET to that local server, so choose an actual page URL. Loopback previews require a paired device with write access; read-only
devices can preview project files only.

Each preview expires after 15 minutes; Refresh opens a new session and reads
updated files. A resource can be up to 20 MiB, with up to 40 MiB and 64 resources
per preview. Large pages are paced to leave relay capacity for ordinary app
traffic and can take several minutes. Page content is not intentionally saved
for offline viewing.

## Implementation boundaries

The companion creates an opaque preview ID bound to the paired device, pane
identity, and canonical working directory. Native Android code retrieves
bounded chunks using the authenticated bridge. The WebView receives only
content under a per-preview synthetic HTTPS origin, never bridge credentials.
It has no native JavaScript bridge, file/content access, or network fallback.
A restrictive content security policy applies to every resource response.

Native Material controls surround the page; the dashboard and conversation
screens are unchanged by this feature.
